# Architecture Decision Records

ADRs preserve decisions whose rationale must survive individual implementation cycles.

## Identified decision set

The following ADRs were identified during project definition and must be consolidated from the approved project context before being treated as final specifications:

- ADR-001 — Web app tablet-first instead of a game engine
- ADR-002 — Open overworld between subject worlds
- ADR-003 — Sequential progression only inside worlds
- ADR-004 — Learning content decoupled from scenery
- ADR-005 — Parametrizable Activity Slots
- ADR-006 — Child-oriented interface without a traditional header
- ADR-007 — Progress communicated primarily through restoration of color
- ADR-008 — Reusable Challenge Templates instead of hardcoded exercises

Until the individual ADR file exists with its rationale and status, this list is an inventory of previously identified decisions, not permission to extrapolate unspecified details.

## ADR template

Each ADR should contain:

- Status
- Context
- Decision
- Rationale
- Consequences
- Alternatives considered, when known
- Related specifications
